# Mail is a window onto Gmail: nothing about a message is stored, and sign-in is Google's browser token flow with no server piece

_Superseded by ADR 0080: Mail is retired._

An email client inside Lifeline could have mirrored the mailbox into the Document store (every message a Document, synced through PocketBase, Gmail kept in step both ways) — rejected: Gmail already syncs to every device, the per-Account sync engine (ADR 0002, 0039) was not built for tens of thousands of rows, the Vault and search would fill with mail, and two-way state reconciliation is where mail clients go wrong. The decision follows ADR 0017's boundary for outside content: **Gmail is the only truth**. Threads and Messages are read live from the Gmail API into a local-only Dexie table (`_mail_cache`, never synced), triage (archive, read/unread, star, label, trash) is written to Google and nowhere else, and a Message enters the Document store only when the user keeps it — as a Handoff to an Intake (ADR 0050): a Clipping, a Task, an Event. Offline shows the cache marked stale, and a triage action offline fails loudly with no queue to replay (ADR 0007's precedent): a queued archive replayed hours later is the wrong outcome. The one Document type is the **Mailbox** — one connected address, Linkable, with a colour — so links and a Base come for free. Gmail only, because that is what the user has; the transport sits behind one provider module, so IMAP could join without touching the domain.

Sign-in is **Google Identity Services' browser token flow**: an access token in memory for an hour, renewed in a Google window on a user click and never on the App's own initiative. No refresh token exists anywhere. Considered and rejected: (a) authorization code with PKCE exchanged through a PocketBase hook route holding the client secret — the refresh token would be the App's to store and protect, and Gmail's restricted scope keeps the OAuth project in "Testing" status, whose refresh tokens expire after seven days anyway; (b) Tauri-only with a desktop client and loopback redirect — no Mail in the browser build, where the phone lives. Consequence accepted: Google accepts only http(s) origins for the token flow, so **Mail works in the browser builds only** and the Tauri shell shows it as unavailable. Nothing sends: reply and compose open Gmail.

## Consequences

- Types: `mailbox` (address, display name, colour slot, Tags; Linkable; opens the Mail screen). Local table `_mail_cache` holds Thread rows and opened Message bodies per Mailbox and Label; deleting a Mailbox purges its rows on that device and changes nothing at Google.
- Labels are Gmail's, listed and applied, never Tags; keeping a Message carries no Label across.
- Reading: HTML bodies sanitised (DOMPurify) and shown in a sandboxed frame, remote images blocked until asked, links opened outside; attachments listed by name and opened in Gmail. Keeping converts HTML to markdown (Turndown) and the receiver's dialog shows it before saving.
- Search is Gmail's query syntax passed through, per Mailbox or across all under All.
- Surface: one App screen (Mailbox switcher with All, Label rail, Thread list, open Thread) as a top-level sidebar row; an Unread tile and a Latest mail Card; "Go to Mail" and "Connect a Mailbox…" Commands. No Daylog, no capture Command.
- `VITE_GOOGLE_CLIENT_ID` is build configuration beside `VITE_PB_URL`; the client's authorised JavaScript origins are the dev and deployed origins.
