# Authors are Library Documents linked many-to-many; the Bibliography is a window, never stored

Adding a book was tedious when the one free-text search missed it: the whole string went to Open Library as `q`, eight hits came back, and the Work kept a single `creator` string with only the first author. The cheap fix — a Title box and an Author box mapped to the providers' `title=`/`author=` parameters, and a "works by this author" lookup flow with nothing persisted — was considered and rejected by the user in favour of the fuller model, because an author is a thing worth linking to from a note. So the Library owns a new Linkable type, **Author** (name as title, `alternate_names` as aliases, an `externalKey` `openlibrary:/authors/OL…A` or empty, a body), and a Work carries **`authors`, a many-target Link field**, in place of `creator`, which is deleted. That field kind did not exist: Core gains **`links`** — a `link` holding several ids, written as a list of wikilinks in frontmatter, an edge in the Graph and a source of Backlinks like any link — rather than the Library keeping a private id list that the Vault could not read (rejected: an Author page with no backlinks is an empty shell, and co-authors, attendees and ingredients will want the kind anyway). A single Link field with `creator` kept as text was rejected too: it lies about comics and co-written books, and keeping the string beside the link means two answers to "who wrote it".

Every existing `creator` string is **migrated once, offline, name-only**: split on `/`, `&`, `,` and ` and `, each distinct name (trimmed, case-folded) becomes one Author with no outside identity in the same held-or-shared scope as its Works (ADR 0048: no type is exempt, so the same name may exist twice across a separation wall, and Merge never crosses it). Resolving online at migration was rejected — it guesses on "John Williams". Identity arrives later: "Find metadata" on one Author, or "Resolve authors" walking the unresolved and applying only a single exact-name hit; both fill key, photo, years and aliases and never rename. Picking a book hit find-or-creates its Authors silently (key, then name or alias), shown as removable chips in step two; the duplicates that still slip through are fixed by an explicit **Merge**, which relinks Works, carries names as aliases and the body, takes the outside identity if the survivor had none, and deletes the loser.

The **Bibliography** — what Open Library says the Author wrote — is fetched when the Author's page opens and **never stored** (rejected: a JSON cache on the Author; hundreds of rows of someone else's data going stale, exactly what ADR 0051 keeps out of the store). Each row says whether it is already yours and on which Shelf; the rest are ticked and added as *To read*, Wanted, no Reason. Same-title rows fold and year-less rows sink behind a "Show all" toggle. Offline there is no Bibliography, only the Author's backlinks.

## Consequences

- Types: `author` (Linkable, body, aliases, `externalKey`, `photoUrl`, `born`, `died`); `book`/`comic` lose `creator`, gain `authors: links → author`. Core: `links` field kind through text mode, the link index, the Graph and Base columns.
- Chrome: no Authors tab. One hidden routed screen, `library/authors/:id`, reached from an author's name on any Work and by "Open in Library" from the Base or Vault; it holds the photo and years, your Works by Shelf, the Bibliography, and Merge / Find metadata in its menu. The Author's Vault page shows backlinks only.
- Add dialog: Title and Author boxes, either alone searches; the Author box offers your own Authors first, then Open Library authors, and picking one narrows the search to that author's key and links the Work. Twenty hits and a "More" that pages the provider that answered; the chain does not restart. Leaving Title empty with an Author picked is the Bibliography's second door.
- Gallery search matches Author names where it matched `creator`. Quick add ("Dune — Frank Herbert") find-or-creates by name. "Find metadata" on a Work fills Authors only when it has none; "Refresh from source" never touches them.
- An Author outlives its Works; deleting an Author unlinks and never deletes them. Deleting a Work never deletes its Authors.
- Rejected on the way: an Open Library key required on every Author (a self-published friend could never be one); a Vault side panel as the only home for the Bibliography (hundreds of rows with tick boxes are a page); a dialog without a URL (the Vault could not send you there).
