# Lifeline — Context

Glossary of domain terms for Lifeline, the personal dashboard/OS. Implementation details live elsewhere.

One shell hosts many sovereign Apps. Apps own their entities and behaviors; they interoperate only through Contracts defined by the Core.

## Glossary

### App
A sovereign domain module (Chores, Stats, Readlist, Tasks…) living inside the shell. Owns its entities, rules, and screens. Never reaches into another App's data directly — all interop goes through Contracts.
_Avoid_: plugin, widget, service

### Core
The neutral part of the system: shell, contracts, sync layer, command registry. Owns no domain entities.

### Contract
An interface defined by Core that an App may implement for one of its entity types (e.g. Schedulable). Carries data shape *and* behavior hooks — the consuming surface calls the hook; the owning App decides what happens. Contracts are how "apps and their data work together" without merging domains.
_Avoid_: capability, trait, API

### Schedulable
The first Contract: an entity that can be placed onto a time surface (calendar, week view). The owning App supplies title/identity/status and behavior hooks — e.g. what completing a placement means, and what happens when a placement's time passes uncompleted (keep / roll forward / drop). A Chore rolls its placement forward until completed; a simple task's placement just passes.

### Timed
The second Contract: an entity that happens at a fixed time on a day (start/end, or all day) and is not work — nothing to complete. Surfaces draw Timed items above the day's Schedulable work. The Calendar App's Events are the first implementation; the owning App may allow moving them to another day.
_Avoid_: appointment (that's an Event, one implementation), block

### Placement
A Schedulable entity's assignment to a day or time slot on a surface. Owned by the surface (calendar), referencing the foreign entity by App + id. Distinct from the entity itself: deleting a Placement never deletes the entity. Subsumes calendar's old "TimeBlock".
_Avoid_: TimeBlock, occurrence, booking

### Surface
A screen that consumes a Contract across all Apps rather than owning a domain (calendar grid, week grid, Today feed, dashboard). Surfaces are general; Apps are specific.

### Command
A named action an App registers with Core, run from the global palette (Ctrl+K): navigation or domain action ("Complete chore…", "Log entry…"). Declares an argument signature from day one; v1 collects args via dialog, inline parsing may come later.
_Avoid_: shortcut, action

### Screen
A user-created, named page composed of Cards on a grid layout (drag/resize). Users create any number. Apps also ship built-in full-page screens; the sidebar lists both.
_Avoid_: page, view, workspace

### Card
A self-contained UI block an App registers for use on Screens — small ("chores due today", "current streak") or large (full calendar grid). The unit of layout composition. A Card is a *kind*; what sits on a Screen is a Card instance. Some Cards are **configurable**: they can't be shown without the user choosing something first (which Stat, which medium, which Event).
_Avoid_: widget, block, tile

### Card instance
One placed copy of a Card on one Screen, with its position and, for configurable Cards, its chosen settings. The same Card may be placed many times on a Screen with different settings (a "Push-ups" tile next to a "Weight" tile). Removing an instance never touches the entity it points at.
_Avoid_: widget, tile

### Task
A unit of work owned by the Tasks App. One-time (optionally assigned to a day) or recurring. Absorbs calendar's old Task/Backlog and week-planner's tasks. Completable; implements Schedulable.
_Avoid_: todo, item

### Occurrence
One instance of a recurring Task, generated by its recurrence rule. Each Occurrence completes and moves independently. Recurring Tasks have no single "done" state — only their Occurrences do. (Period-reopen semantics are not a Task concept; that need is served by the Chore App.) Occurrences are derived, never stored; only the ones that were moved or completed leave a sparse per-Occurrence override keyed by task + source day.
_Avoid_: period, instance

### Unassigned
A one-time Task with no day yet. It lives in the pool (the "Unplaced" column of the week Surface) until dropped on a day. Recurring Tasks are never Unassigned.
_Avoid_: backlog, inbox, someday

### Move
Dragging a Schedulable item to another day on a Surface. The owning App decides what a move means (a Task changes its day; an Occurrence gets an override); an App that doesn't own moves gets a Core Placement pin instead. Moving an item back to the pool is only possible for Apps that own moves.
_Avoid_: reschedule, pin (a pin is the Core fallback, not the concept)

### Event
A thing that happens at a fixed time (start + end, or all-day), owned by the Calendar App. Not work, not completable. The Calendar App owns Events and the calendar Surfaces; it no longer owns Tasks.
_Avoid_: appointment, meeting

### Stat
A named series the user tracks (push-ups, weight, workouts, countries visited). Defines what is tracked and how values are read — one of four kinds: **Additive** (entries add up), **Measurement** (point-in-time readings), **Boolean** (a day was done), **Collection** (distinct items collected, optionally against a universe size shown as a denominator). Holds no totals; kind is fixed after creation. Goals/targets are out of scope.
_Avoid_: metric, counter, habit (a habit is a Boolean Stat), goal

### Entry
One logged event of a Stat: a value and the moment it happened (user-settable, backdating allowed), plus an item name for Collections. Totals, streaks and distinct counts are always derived from Entries, never stored; duplicates are collapsed at derivation, never rejected.
_Avoid_: log, record, data point

### Streak
A Boolean Stat's run of consecutive marked days. The current streak ends today or yesterday — an unmarked today doesn't break it. Derived, period-independent.

### Media item
A work (not an edition) of any medium — book, comic, movie, series, album, game — living on two independent axes: **Acquisition** (Wanted / Owned / Borrowed / Gone) and **Engagement** (Unstarted / In progress / Done / Abandoned — each medium supplies its verbs: read, watched, played…), plus the orthogonal **Studied** mark and, optionally, the **Reason** it was added.
_Avoid_: book (one medium), title, copy, edition

### Nightstand
Per medium, the small capped set of Media items currently claiming attention — both in progress and queued. A Slot is held for the whole time an item is in progress and is freed only by finishing or abandoning (or an explicit "back to backlog"). Caps are fixed in code, not settings. A Wanted item on the Nightstand is the instruction to buy it *now* — it heads the Shopping list.
_Avoid_: queue, TBR, wishlist, shelf, priority

### Backlog
Every Media item not on a Nightstand — an unranked pool, including done and gone items.
_Avoid_: TBR, library, inbox

### Shopping list
Every Wanted Media item, wherever it lives: Nightstand ones first (next up — buy now), then the rest of the wish list, oldest first. Marking one as acquired takes it off the list.
_Avoid_: wishlist (that word hides the buy-now head of the list), cart
